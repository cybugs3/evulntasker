System database

File database on this server. Default for first install.

Uses this Linux machine. Install PostgreSQL here first (RHEL: dnf install postgresql-server), create a database and role, then save. Password is optional if pg_hba.conf uses peer or trust for local connections.

CVEs, assets, sources, tickets, and audit logs go to the selected database. Existing SQLite data is not copied automatically. Tables are created if they do not exist.

System

Dangerous maintenance. This does not change the database connection, input sources, or integration settings.

Reset system data

Permanently deletes every row in the two working tables:

  • Internal systems — organization products you added or imported
  • Incoming CVEs — vulnerabilities ingested or entered, plus pipeline history, tickets, and detections

Input feeds

Configure how EVulnTasker receives vulnerability intelligence. The source name you set here is what appears on Manage Input Sources.

Local folder

Drop any text into this folder — .txt, HTML, CSV, JSON, logs. EVulnTasker extracts CVE IDs with regex (for example CVE-2024-3094).

Must be a real folder on the EVulnTasker Linux host (not a path on your PC). Test path checks the value in this field.

SMB / CIFS share

Text files (.txt, .csv, .json, .md). CVE via regex; vendor/product/version from labels, CSV/JSON, or CPE. Use the same AD account for every location.

Outlook / Exchange (on-prem)

Each unread mail is scanned for CVE IDs and optional vendor/product/version in the body.

ATOM feeds

Interfaces from Vulnerability Repositories are listed here on install (NVD, EPSS, and ATOM/RSS feeds). Change a URL, add another feed, or delete one. Enable polling only fetches ATOM/RSS — NVD and EPSS stay enrichment lookups.

Enrichment

After extract, before Internal systems matching.

Look up NVD / EPSS and, if configured, rewrite the description with AI. Then match the CVE against Internal systems.

Internet intel URLs and AI keys stay saved either way. They are used only while this stage is enabled.

Internet intel AI modules

Internet intel

Enrichment is disabled. NVD, EPSS, and AI will not run until you enable the stage on the Enrichment tab. You can still save URLs and keys here.

Built-in lookup sources are created on install. Change the URL, turn lookup on or off, add another endpoint, or delete a source. Nothing is called until Enrichment is on and the source’s Enable lookup switch is on.

Applies to NVD, ATOM feeds, Local, SMB, and mail. CVE IDs whose year is earlier than this date are skipped.

AI modules

Optional. Runs only while Enrichment is enabled.

The selected provider rewrites the CVE into a clear owner-facing description for Jira, and fills missing fields after NVD/EPSS.

  1. Turn Enrichment on in the Enrichment tab, or the pipeline skips this stage and matches ingested fields against Internal systems.
  2. When enrichment is on, Python (NVD + EPSS) runs first for scores and structured fields.
  3. If a provider is enabled with a key and mode is EVulnTasker AI, the model rewrites the CVE description so owners can see what the vulnerability does — and fills any missing vendor/product fields.
  4. If the module is off, has no key, or mode is Org LLM only, the NVD/ingest wording is kept and used in Jira as-is.

Only one AI module can be enabled. Turning another on disables the previous one.

Inventory APIs

Coming later. For now, Internal systems is filled by hand or CSV on the Internal systems page. These APIs will teach the catalog from CMDB / Sonatype / ITNM when that work starts.

Local CMDB

Pull the full asset list into the local catalog. Matching does not call this API per CVE.

Sonatype / Nexus

Sync applications and components from Sonatype Nexus Lifecycle / IQ into the local catalog.

ITNM / network discovery

IBM Tivoli Network Manager or a similar discovery API. Devices are synced into the local catalog (vendor, product, type, version).

Ticketing

Open owner and threat-hunting tasks in Jira, Monday.com, email (SMTP mail relay), or an internal CRM.

Connection settings shared by all providers (except Monday.com API host).

Monday.com uses api.monday.com — put your API token in the password field above.

Lab / external mail: send owner and hunt tasks through an SMTP mail relay (Postfix, Exchange connector, or any SMTP smart host). Recipients can be any address the relay is allowed to send to.

Owner tasks go to owner_email on each matched Internal system — not one shared mailbox. Hunt tasks go to the hunt address below. Design the mail body in the Message tab using AI JSON field names.

Mail relay

Plain SMTP on port 25. Use STARTTLS (587) or SMTPS (465) when the relay requires encryption.
