System database

File database on this server. Default for first install.

Uses this Linux machine. Install PostgreSQL here first (RHEL: dnf install postgresql-server), create a database and role, then save. Password is optional if pg_hba.conf uses peer or trust for local connections.

CVEs, assets, sources, tickets, and audit logs go to the selected database. Existing SQLite data is not copied automatically. Tables are created if they do not exist.

Reset

Dangerous maintenance. This does not change the database connection, input sources, or integration settings.

Reset Internal systems

Permanently deletes every row in the Internal systems catalog:

  • Internal systems — organization products you added, imported, or learned from CMDB / Sonatype / ITNM
  • Asset matches — CVE-to-system links built from that catalog

Delete Incoming CVEs

Permanently deletes every CVE stored by EVulnTasker:

  • Incoming CVEs — vulnerabilities ingested or entered
  • Pipeline history — ingest events, tickets, and detections

Input feeds

Connection details and poll interval live here. Enable, pause, and Sync now are on Input Sources. Sync now pulls once even if the feed is paused; Enable only turns on automatic polling.

Applies to every incoming path — Local, SMB, Exchange, ATOM, inline CVE, and Debugger. CVEs older than this date are ignored. NVD/EPSS lookups still run by CVE ID only for records already stored.

Local folder

Drop any text into this folder — .txt, HTML, CSV, JSON, logs. EVulnTasker extracts CVE IDs with regex (for example CVE-2024-3094). Enable auto-poll on Input Sources. Sync now pulls once without turning polling on.

Must be a real folder on the EVulnTasker Linux host (not a path on your PC). Allowed roots: /tmp, /var/evulntasker, /opt/evulntasker/inbox, and data/inbox. Add another root with EVULNTASKER_LOCAL_INGEST_ALLOW. Test path checks the value in this field.

SMB / CIFS share

Text files (.txt, .csv, .json, .md). CVE via regex; vendor/product/version from labels, CSV/JSON, or CPE. Use the same AD account for every location. Enable auto-poll on Input Sources. Sync now pulls once without turning polling on.

Outlook / Exchange (on-prem)

Each unread mail is scanned for CVE IDs and optional vendor/product/version in the body. Enable the mailbox listener on Input Sources. Poll now pulls once without turning polling on.

ATOM feeds

Add or edit ATOM/RSS URLs and the fetch interval. NVD and EPSS in this list stay enrichment lookups — they are not polled. Enable or pause each ATOM feed on Input Sources. Fetch now pulls enabled ATOM feeds; Sync now on a paused feed still pulls that URL.

Enrichment

After extract, before Internal systems matching.

Look up NVD / EPSS and, if configured, rewrite the description with AI. Then match the CVE against Internal systems.

NVD and EPSS endpoints stay in Settings → Feeds → ATOM feeds. Enable lookup on Input Sources. Turning this off does not disable AI for extract or matching — use the AI modules tab for that.

ATOM feeds AI modules

AI modules

AI is optional. Off until you save an API key. Then the model can extract a CVE ID regex missed, rewrite ticket text, or infer an owner when Internal systems has no match.

No LLM calls anywhere. Tickets still open from Ticketing using ingested/NVD fields and the Message templates.

AI is off. Extraction uses regex only, enrichment does not rewrite text, and matching uses Internal systems only. Tickets still open from the Ticketing tab with the Message templates — AI is not required to create them.

  1. This switch is independent of Enrichment. Disable it if the organization must not call an LLM at all.
  2. Extract: regex first; the model is used only when no CVE ID is found.
  3. Enrich: NVD/EPSS run first when Enrichment is on. If mode is EVulnTasker AI, the model may rewrite the owner-facing description and fill missing vendor/product.
  4. Match: Internal systems first. The model may infer an owner only when nothing matches.
  5. Act: Jira, Monday, Email, or Internal CRM still open from Ticketing. Without AI the ticket uses ingested/NVD wording as-is.

The selected provider rewrites the CVE into a clear owner-facing description for tickets, and fills missing fields after NVD/EPSS.

Only one AI module can be enabled. Turning another on disables the previous one.

OpenAI ChatGPT via the official API. Requires an API key from platform.openai.com. A ChatGPT website login or Plus subscription is not an API key — this app cannot call ChatGPT without a key.

Azure OpenAI deployment. Use your resource endpoint and deployment name in the API base URL.

GitHub Copilot or enterprise endpoint. Requires an organization token with Copilot access.

Inventory sources

CMDB, Sonatype, and ITNM are not pipeline steps. They teach the Internal systems catalog: the catalog is built at setup (manual rows or CSV), then sampled on a schedule (typically every 24 hours). Only new equipment is inserted. Matching always reads the local catalog, never these APIs per CVE. Connections stay idle until a live CMDB / Sonatype / ITNM host is available. Seed or edit rows on the Internal systems page.

Local CMDB

Learns new configuration items from the CMDB and inserts only equipment that is not already in Internal systems. Not called when a CVE is matched.

Sonatype / Nexus

When Enable is saved, EVulnTasker pulls IQ applications and the libraries from each application's latest report into Internal systems (new rows only). Matching still reads the local catalog, never IQ per CVE. Scheduled refresh uses the 24-hour inventory sync switch.

ITNM / network discovery

Learns new devices from IBM Tivoli Network Manager or a similar discovery API (vendor, product, type, version). Inserts only new equipment. Matching still uses Internal systems only.

Ticketing

Enable each system separately. After extract and match, EVulnTasker opens owner and hunt tasks from ingested/NVD fields and the Message templates. AI is not required — it only rewrites wording when AI modules are enabled.

Connection settings shared by all providers (except Monday.com API host).

Monday.com uses api.monday.com — put your API token in the password field above.

Send owner and hunt tasks through any SMTP server: an internal mail relay, Exchange connector, Microsoft 365, Gmail, or another provider the relay is allowed to send through.

Owner mail goes to owner_email on each matched Internal system. Permanent email always gets a copy when that address is filled. Fallback is used only when a matched system has no owner email. Leave either address blank to skip sending to it. Layout is in the Message tab.

SMTP server

Plain SMTP on port 25. Use STARTTLS (587) or SMTPS (465) when the server requires encryption.

Who receives mail

Jira: GET /rest/api/3/myself with the saved token.

Notification message

Layout of the owner and hunt emails. The AI enrichment step returns JSON; each JSON key can be placed in the message as {{ '{{name}}' }}.

Click a field name to insert it at the cursor. Extra keys the model returns also work, using the same {{ '{{key}}' }} syntax.
